# Lua によるシーン構成とイベント処理（設計案）

## 目的

Lua からシーンツリーを組み立てる方法と、C++で作成したシーンにLuaのイベント処理を付ける方法を提供する。利用者がどちらか一方に固定されないよう、同じLua実行環境、型登録、シーン参照の仕組みを共有する。

この文書は設計案であり、実装前の検討事項を含む。合意後に `spec/` の確定仕様へ移す。

## 現状との対応

- `Scene` は `AddScene` と `CreateScene` で子シーンを持つ。位置、拡大率、表示状態などの基本プロパティも提供している。
- `SceneManager` は現在シーンを保持し、読み込み、更新、解放を管理する。
- `Signal` はコールバック登録と切断に対応する。`Button`、`Collision`、`MouseCollision` などがイベントを公開する。
- `Novot.vcxproj` はVisual Studioの静的ライブラリ設定で、Luaのヘッダーやライブラリはまだ参照していない。
- 作業ディレクトリの隣にLua 5.5.1ソースがある。ただし兄弟ディレクトリへの参照は利用者の環境に依存するため、配布可能なビルド方法を別途決める。

## 利用モデル

### Luaがシーンツリーを定義

Luaファイルは、エンジンが登録したシーン型とプロパティ、子シーン、イベント定義を返す。エンジン側のファクトリがテーブルを読み、C++オブジェクトを生成して親子付けし、プロパティを適用する。

```lua
return {
    type = "Scene",
    name = "Title",
    children = {
        {
            type = "Sprite2D",
            name = "Logo",
            texture = "assets/title.png",
            position = { x = 640, y = 180 }
        },
        {
            type = "Button",
            name = "StartButton",
            position = { x = 640, y = 500 },
            events = {
                left_pressed = "on_start_pressed"
            }
        }
    }
}
```

同じファイルまたは指定したスクリプトにイベント関数を定義する。

```lua
function on_start_pressed(button, event)
    print("start")
end
```

最初の対応型は `Scene`、`Object2D`、`Sprite2D`、`ColorRect`、`Button` を候補とする。型名とプロパティを登録制にして、ゲーム側の派生型も追加できるようにする。

### C++シーンへLuaスクリプトを添付

C++側で通常どおりシーンを構成し、Luaスクリプトをアタッチする。Lua側の `on_load`、`on_update`、`on_release` や名前付きイベント関数を、登録されたライフサイクルと `Signal` に接続する。

```lua
function on_load(scene)
    scene.position = { x = 100, y = 80 }
end

function on_left_pressed(button, event)
    print("clicked")
end
```

アタッチはファイルパスを受け取るAPIとし、Lua実行環境の所有者を明確にする。たとえばシーン単位のスクリプトコンポーネントを設け、シーンの解放時にイベント接続を切り、Lua参照を破棄する。

## 共通アーキテクチャ案

1. **LuaRuntime**: Lua状態の生成・破棄、標準ライブラリの公開範囲、スクリプト実行、エラー整形を担当する。初期案ではゲームまたはエンジンが所有する状態を一つ用意する。
2. **LuaBindings**: `Vector2D` と選定したシーン型の生成、読み書き可能なプロパティ、メソッドを登録する。LuaからC++オブジェクトを参照するときは寿命が切れたオブジェクトを使えない仕組みにする。
3. **SceneFactory**: 型名からC++シーンを作る登録表を持ち、Luaのシーン定義を検証してツリーを構成する。
4. **LuaSceneScript**: Luaファイルを読み、ライフサイクル関数を呼び出す。`Signal` に接続した関数の参照と接続IDを保持し、解放時に切断する。
5. **Lua error reporting**: ファイル名、関数名、Luaのスタック情報を含む診断をDebuggerへ出す。ロードやコールバックの失敗はエンジン側へ伝え、ゲーム全体を不意に停止させない方針を候補とする。

両モデルは同じ型バインディングとLua状態を使う。シーン定義のイベント名は、対応する `Signal` とシグネチャが一致するか生成時に検証する。イベント値はLuaのテーブルへコピーし、C++の参照をLuaへ長期保存させない。

## Luaの公開範囲

- 初期公開候補: 名前、位置、オフセット、拡大率、アルファ、可視性、有効状態、子シーン追加、名前検索、選定済みのシグナル登録。
- `Vector2D` はLuaテーブルとの相互変換で扱う。
- C++の任意関数やDxLib APIをLuaへ一括公開しない。必要な操作だけを明示登録する。
- Luaの標準ライブラリは必要最小限から開始し、ファイルI/OやOS操作を許可する範囲を設定可能にする。
- Luaからのシーン追加とイベント発火が更新中に起きる場合の安全性を定義する。

## ビルドと配布

LuaをNovotへ組み込む際は、利用者側プロジェクトが同じ依存を再現できることを条件にする。候補はLuaソースをリポジトリに含めて静的ライブラリへ組み込む方法、またはLuaのビルド成果物を明示依存として配布する方法。兄弟ディレクトリの固定パスを製品のビルド要件にしない。

Lua C APIを直接使うか、バインディングライブラリを追加するかを決める。追加依存を選ぶ場合はライセンス、対応C++規格、Lua 5.5対応、ビルド再現性を確認する。

## 段階的な実装案

1. Lua依存の取り込み方と所有モデルを決定し、全構成でビルドできる状態にする。
2. LuaRuntime、エラー報告、Vector2D、基本シーン型のバインディングを実装する。
3. C++シーンへのスクリプト添付と、`on_load`・`on_update`・`on_release` の寿命管理を実装する。
4. `Button` の押下など少数のシグナルをLuaへ接続する。引数の変換と切断を確認する。
5. 登録型を使うシーンファクトリ、Luaのツリー定義、プロパティ適用、イベント名解決を実装する。
6. サンプルLuaファイルと利用手順を追加し、エラー、再ロード、シーン切り替え時の挙動を確認する。

## 決める必要があること

- Lua 5.5.1を採用するか。隣のソースを使う場合、ソースをリポジトリに含めるか、別途入手する手順を用意するか。
- Lua状態をゲーム全体で共有するか、シーンごとに分けるか。
- 初期対応するシーン型と、公開するイベント・プロパティの範囲。
- シーン定義をLuaの戻り値テーブルにするか、`Scene.new` のようなビルダーAPIにするか。
- Luaの更新コールバックを毎フレーム呼ぶか、必要なシーンだけ登録可能にするか。
- スクリプトエラー時にそのスクリプトを無効化するか、シーンの読み込みを失敗させるか。
