# Map1 のLua移行に必要な拡張案

## 背景

EnvSoundEnc の `Game/Explorer/Map/Map1.cpp` は、JSONマップの読込だけでなく、背景・カメラ範囲・衝突領域・マップ遷移・雨音と雨シェーダー・水たまり・車の出現、さらにDebug用マップエディターを構成しています。現行Luaシーン機能（`docs/LUA_SCENES.md`）は汎用シーン7型の生成、共通プロパティ、Button/AnimatedSprite2Dイベント、既存シーンへの基本ライフサイクル添付が中心です。ゲーム固有シーンをLua定義から生成・操作するAPIはまだありません。

そのため、Luaファイルに既存のJSON内容を単純に移すだけでは `Map1.cpp` の置換になりません。ゲーム固有型やランタイムサービスをLuaへ公開する設計が必要です。

## Lua移行の対象案

マップスクリプトは、データと振る舞いをひとつの定義として持つ案です。例：

```lua
return {
    name = "Map1",
    camera = { min = { x = 0, y = 0 }, max = { x = 3500, y = 720 } },
    backgrounds = {
        { texture = "map/0/bg.png", position = { x = 0, y = 0 }, y_sort = 0 },
        { texture = "map/0/buildings.png", position = { x = 0, y = 0 }, y_sort = 1 },
        { texture = "map/0/bar.png", position = { x = 1275, y = 0 }, y_sort = 2, y_sort_offset = 0.7 },
    },
    spawns = {
        { name = "default", position = { x = 100, y = 300 }, default = true },
    },
    collisions = {},
    sounds = {},
    on_load = function(map) end,
    on_update = function(map, dt) end,
}
```

これは移行先の記法案であり、現行APIでそのまま動作する仕様ではありません。関数を返却テーブル内に置く形式を採用するか、現在のトップレベル関数形式を使うかも実装時に揃える必要があります。

## 不足しているLua API

1. **マップ定義ローダーと検証**: 相対アセットパス、必須項目、既定値、ロードエラーの診断、Lua定義から実行時マップを生成する入口。
2. **ゲーム固有シーン型**: `Player`、`SoundSource`/コンテナ、水たまり、車などの登録・生成、および必要なプロパティ操作。生成可能型と型固有プロパティを明示的に制限する。
3. **衝突領域**: 頂点、レイヤー、マスク、通過可否、領域進入/退出イベント、領域音の設定。
4. **遷移**: 遷移先マップとスポーン名（数値indexより名前を推奨）の指定、遷移API、連続遷移防止。
5. **マップ/カメラサービス**: カメラ範囲、スポーン選択、プレイヤー追従などをLua定義へ反映するAPI。
6. **音響**: 音源種別、パス、位置、音量、ループ、空間減衰/追従、再生停止、およびプレイヤー歩行など既存ゲームイベントとの接続。
7. **画面シェーダー**: 雨シェーダーの選択、定数バッファ更新と解放、シーン切替時の後始末。DxLibや任意C++関数を無制限に公開せず、用途を限定したAPIとする。
8. **Luaからのイベント購読**: プレイヤーの歩行/待機、衝突領域の進入/退出、タイマーなど、Map1で必要なイベントの接続と解放時切断。
9. **エディター互換性**: Debug用エディターでJSONとLuaをどう扱うか、編集・保存形式をどうするか。Lua定義を編集しない場合も、ランタイム生成物と編集データの対応を定義する。
10. **後始末とエラー**: Luaコールバック失敗時の報告、イベント購読解除、音源停止、衝突/シェーダー解放、シーン遷移時の安全性。

## 進め方の案

- マップ定義ローダーを汎用 `LuaSceneLoader` と分離するか、共通のLua状態・バインディング基盤を共有した専用 `LuaMapLoader` として設計する。
- 先にMap1が使う最小API（背景、カメラ範囲、スポーン、衝突/遷移、音響、雨エフェクト、必要なイベント）を確定し、小さい縦切りで実装する。
- JSONマップエディターとの互換を保つ期間が必要なら、JSONを読み込む既存経路を残し、Luaマップを別形式として段階導入する。
- Luaファイルのサンドボックス方針と、現行の全標準ライブラリ公開を継続するかを合わせて判断する。

## 未決事項

- Luaをマップの唯一のデータ形式にするか、JSONと併存させるか。
- Debugエディターの編集・保存対象をLuaへ広げるか、当面JSONを維持するか。
- マップ遷移先をファイルパスとマップIDのどちらで指定し、スポーン先を名前とindexのどちらで指定するか。
- ゲーム固有オブジェクトをLua定義から生成する範囲と、C++側に残すゲームプレイ責務の境界。
- Luaからシェーダーや音響を直接操作するAPIの公開範囲。

この文書は検討案であり、確定仕様ではありません。
